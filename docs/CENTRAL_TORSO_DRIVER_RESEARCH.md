# Central torso vector driver: frozen development screen

28 October 2026. Production remains `872c9f7`, compiler9. This research tests one measurement change with the current causal engine and default thresholds. It neither changes a camera model nor establishes anatomical joint angles.

The existing ipsilateral elbow–shoulder–hip angle includes the lateral offset of surface shoulder/hip markers. Test the angle between the observed selected upper-arm vector (elbow minus shoulder) and the central torso-down vector ((left hip+right hip−left shoulder−right shoulder)/2). This unsigned 0–180 degree vector relation is mathematically distinct from clinical shoulder abduction and from native Euler components. It may reduce surface-marker lateral-offset effects; no performance gain is assumed.

All four torso markers plus the selected elbow must be finite, nonzero original acquisition samples; either collapsed ray stays missing. No counterpart elbow, imputation, coordinate correction, inferred joint centre, confidence prediction or pose repair is used. Preserve original coordinates and full uncut100Hz times. Derived vectors do not replace recorded markers. Their named descriptors are `angle.left_arm_central_torso` and `angle.right_arm_central_torso`, in a separate research pipeline/backend identity.

The engine's current exercise policy consumes its shoulder driver slot. The test-only replay explicitly projects the new named descriptor into that slot for `m07` only, on both reference and source. It removes the old slot first, so missing central-torso evidence cannot fall back to an easier marker proxy. This declared research projection is not a new definition of the production `angle.*_shoulder` feature. It cannot be promoted without distinct product feature semantics, MP33 observability/provenance work and full regression review.

Use only the existing development subjects01–04, all16 complete recordings and160 original repetitions, with the same right-side shoulder and left-side squat variants, labels, episode bounds and one-to-one event matching. Keep missing/unmatched events in denominators. Fix the reference to subject01, except subject01 uses02; choose no source-dependent reference, side or model. Apply no threshold search. Squat features and all squat attempt outputs must remain identical to the paired current baseline. The comparator sees no publisher source label, episode bound or future frame.

Freeze implementation, tests, current production dependencies, publisher archives and development exports before reading source outcomes. Run paired baseline/candidate with compiler9, inspect original development marker frames plus both angle traces, and preserve all results even if the candidate regresses. This development screen can only authorize a separately frozen validation experiment if precision≥.90, good-rep recall≥.70 and coverage≥.80 across the entire160-rep cohort. Validation05–07 and final08–10 are forbidden in this experiment. Development pass earns no readiness points. No new human annotation, training of raw pose-network weights or human live-rep accuracy claim is authorized.

Marker order and sampling derive from the already archived [original UI-PRMD descriptor](https://pmc.ncbi.nlm.nih.gov/articles/PMC5773117/), Positions table and100Hz Vicon acquisition. Licensed inputs remain the publisher's [PDDL1.0 archive](https://zenodo.org/records/23104965). Surface-marker geometry and original binary rep labels remain separate from MediaPipe confidence and camera ground truth.

# Denser reference extraction research

The 25 October candidate tests whether retaining original frames at a 33 ms minimum interval, rather than 66 ms, improves calibration of the fixed sixteen complete reference uploads. MediaPipe VIDEO tracking consumes a different observed prefix at the denser cadence. This can change landmark estimates even at shared timestamps; it is an input/extraction experiment, not an isolated change in the rep algorithm or trained landmark weights.

The protocol freezes Full model identity, 960-pixel maximum edge, the original source-PTS decoder, uncapped reference duration, all sixteen source hashes, the preceding 32-choice registry and ordinary/bounded reference fits before inference. Keep all image/world coordinates, visibility and presence for all 33 landmarks. Do not interpolate timestamps, coordinates, confidence or labels. The research fingerprint is `mp33-raw-world-dense33-research/1`, separate from the established pipeline. Existing reference/source caches are preserved.

Screen each reference/side under the unchanged production confidence, range, dwell, coverage, noise, minimum-cycle and 80% reconstruction requirements. Existing Full/Heavy and ordinary/bounded choices retain priority; denser Full is eligible for research only where all established choices were unavailable. Source outcomes and weak whole-clip labels cannot choose between candidates. No UI-PRMD validation/final trajectories are opened.

The first screen reads references only. A newly reconstructable reference alone earns no readiness points: source replay must use a coherent declared extraction pipeline, counts/verdicts must be audited and any production promotion requires scoped JVM/native verification and a fresh APK. A gain in self-reconstruction is not independent human-rep precision. The fixed 32-reference denominator, six-policy set and all independent gates stay unchanged.

Fixed timestamped QA uses original RGB at the nearest shared observed PTS to 6,000 and 10,000 ms in reference 001 front squat, 005 side squat and 001 side push-up. Display original RGB alongside unmodified raw old/dense pose overlays. These frames are diagnostics, not new manual correctness annotations. Preserve both successful and failed outcomes.

The code/protocol were committed before launching the extraction. `scripts/extract_dense_reference_candidate.py` verifies protocol/source/input receipts before inference; `:core-motion:denseReferenceCalibrationAudit` performs the reference-only screen; `scripts/plot_dense_reference_extraction.py` creates timestamped QA. The results and promotion decision follow below. Production readiness remains 42.5/100 and the previously verified APK remains current.

## Outcome: no additional original evidence

The candidate was frozen in `e4e363d` before inference. All sixteen Full extractions completed in 133.92 seconds of wall time with three bounded desktop workers; this timing is not Android or per-frame performance. The experiment recovers **zero** additional reference/side configurations under either fit. Established selections remain 12/32, with no losses and no promotion.

The original streams are all 15 FPS. Their 7,191 complete reference frames were already present in the 66 ms caches. The 33 ms extraction retains exactly the same 7,191 original timestamps and all per-frame fields other than inference timing, including every image/world coordinate, visibility, presence, feature value and detection pattern. Finer nominal sampling cannot add images absent from the recording. No duplicated or interpolated frames are substituted. A distinct research fingerprint does not make identical evidence a newly recovered reference.

Six original RGB frames and twelve corresponding raw pose overlays were inspected at the frozen timestamps. The squat and push-up overlays match across the two extraction settings. The side squat view has frame-edge truncation and the gym scenes contain other people/background objects; increasing a sampling setting cannot resolve those image limitations. These observations are diagnostics and do not assign new rep correctness labels.

The first trial exposed a missing efficiency check: native source frame availability should have been audited before repeating model inference. `scripts/audit_reference_source_cadence.py` now reads original presentation timestamps with FFprobe, verifies that cached samples are actual source timestamps and reports whether unsampled original frames remain, without invoking a pose model. Its optional dense comparison detects changes in confidence, coordinates, timing and other retained fields. Run this preflight before any future sampling-density experiment. It refuses to overwrite completed audit reports.

All 220 core-motion JVM tests and 72 Python tests pass without failures/skips. No main production source changed; the prior 27 native functional tests and frozen control checkpoint still bind engine `c610706`. No native suite, source replay, independent-label evaluation, new APK or ten-minute soak is claimed for this experiment. Validation/final skeletal trajectories remain unopened in this work. The model weights, raw established caches, reference targets, fixed rubric and readiness score remain unchanged. See `models/dense-reference-extraction.provenance.json` for immutable receipts.

Reject denser sampling as a recovery method for this particular 15 FPS cohort. Future extraction research must change a supported measurement mechanism, such as explicit person-region preprocessing with invertible image-coordinate provenance, rather than invent intermediate frames or widen the comparison thresholds. Independent per-rep RGB truth and cross-person reference-depth generalization remain unresolved. Readiness stays **42.5/100**, with live human-rep precision unknown.

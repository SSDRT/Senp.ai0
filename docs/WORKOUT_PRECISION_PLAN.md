# Reference-based workout precision — implementation plan

Continue branch `codex/live-pose-accuracy` from `83a94d6`. Scope: local pose/movement measurements, reference compilation and live suggestion triggering. No paid service, cloud inference or front-end redesign.

1. **Measurement reliability.** Retain confidence for each angle/distance, using the least reliable constituent joint and normalization anchor. Add body-line angles and torso-normalized hand/foot distances for movements not described by an elbow/knee angle alone. Do not coach people to match another person's limb lengths. Missing confidence must stay unusable. Projected 2D coaching remains disabled by default; enabling it for release requires image-dimension metadata and aspect/view calibration.
2. **Any demonstrated workout.** Preserve generic phase-aware action compilation, add explicit/auto static-hold compilation, record the reference coordinate evidence, and expose every feature as coachable, insufficiently observed, context-only or unsupported. An arbitrary workout ID is accepted; naming a workout does not establish validated coverage.
3. **Threshold decisions.** Add configurable, unit-bearing per-feature trigger/release thresholds outside the learned robust reference range. Widen thresholds conservatively for measured reference variability. Require reliable phase/feature evidence and continuous elapsed-time persistence; reset on gaps, subject/mirror/source changes and unavailable joints. Add hysteresis, release dwell and repeat cooldown. Return both active suggestions and one-shot trigger events with complete measurement/threshold provenance. Avoid learning a user's mistake as the new target.
4. **Live integration.** Use the precision layer in the generic live processor, including distance cues, with bounded live history and immediate suppression of uncertain cues. Recheck finite-action completion against current observations. Keep offline comparison behavior and frozen serialized contracts intact.
5. **Validation and delivery.** Test exact boundaries, persistence/release/cooldown, threshold overrides, noisy observations, missing/weak joints, wrong action, static holds, mirrored motion, irregular FPS, body-size/view/source changes and long-running bounded state. Run a deterministic multi-family Monte Carlo trigger benchmark with known injected errors, report false triggers/precision/recall and trigger delay, and exercise the real Android model/camera path. Deliver tests, detailed feature coverage, measured limitations, local commit, APK and reproducible reports.

Implementation uses the existing Apache-2.0 MediaPipe/BlazePose engine and pure Kotlin robust statistics, phase recognition and threshold state machines. Primary references: [MediaPipe pose classification](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/pose_classification.md), [Google's classification guidance](https://developers.google.com/ml-kit/vision/pose-detection/classifying-poses), and [Pose Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker).

The requested human-level precision, every possible exercise, expert-correct technique, equipment/load/contact/force, fine spine/finger mechanics and every mobile camera are not established by single-camera pose output. Release requires independent expert annotations across exercises, subjects, views and devices, with held-out PCK/angle error and suggestion precision/recall. Synthetic ground truth can validate the trigger logic, not establish human-level landmark accuracy. These remaining limits must be explicit rather than silently treated as supported.

Implementation and automated validation of steps 1–5 are complete for the generic Android reference-action engine. Optional Heavy inference is also available with verified model provenance. Human-labelled accuracy and the device release matrix remain open validation gates; see `WORKOUT_PRECISION_VALIDATION.md` for exact coverage, evidence and the native stability finding.

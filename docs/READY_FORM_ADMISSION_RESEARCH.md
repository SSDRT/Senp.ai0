# Compatible-start admission candidate

27 October 2026. This is a frozen candidate experiment, not a demonstrated human-rep accuracy gain. The current verified production engine is `c610706` and readiness is 45/100 before this experiment.

The existing engine arms from a visible ready driver and visible companion angles, without requiring the start pose to agree with the uploaded demonstration. Two regression methods reproduce an accepted constructed cycle after an incompatible start, including a previously armed session whose start form subsequently changes. Each covers six policies, two sides, two mirror mappings and four cadences, with a subsequent fresh-cycle recovery control. The preceding engine fails both methods; near-compatible start deviation and corrupting only the unmeasured limb remain accepted. These angular controls are not human correctness labels.

The candidate requires existing acceptable **demonstrated-reference** bands during ready dwell and revokes arming when incompatible visible evidence arrives before departure. It leaves angle/confidence/range/dwell/path/fault/reconstruction thresholds unchanged, preserves raw evidence and still requires a fresh compatible observed start. Absolute technique targets retain their existing active-attempt confirmation/rejection behavior, including a demonstration that itself violates technique guidance. Reference compiler identity advances to `/6`, invalidating older self-reconstruction keys; schema `/5` remains unchanged.

One research-side-binding unit expectation changes deliberately: an incompatible start now emits no attempted rep instead of an active rejected event; the driver-only side/mapping/lock-time comparisons remain exact. The existing technique-guidance rejection test is retained unchanged. The frozen 2,688 controls, 124 corruptions, rubric and human-label denominators are not edited.

Check all core tests, the unchanged generated controls, then replay only already-opened skeletal development subjects 01–04 with original references/labels and timing. **Reject promotion if any previously counted correct development rep is lost, any new incorrect count appears, or a frozen control fails.** This conservative promotion rule prevents treating blanket withholding as accuracy improvement. ## Decision: rejected after validation; production restored

Candidate source/protocol were frozen in `b0adbd7`. All 2,688 unchanged generated controls pass. Development retains all 31 counted correct reps and removes one of 27 incorrect counts, giving 54.39% counted-event precision, unchanged 38.75% good-rep recall and lower 49.38% coverage. This initially passes the prospective no-correct-loss/no-new-incorrect-count development gate. It does not satisfy the independent readiness thresholds or establish camera accuracy.

All eight unchanged Full/Heavy × ordinary/bounded × capped/complete camera-input replays complete. The reference-only selector retains 10/32 capped and **12/32 complete** references with no losses or gains. Source outputs change: capped qualified events fall 18 → 12 and complete events 31 → 19. These are overlapping source-run outputs, not correct/incorrect rep counts; the videos have only whole-clip labels. Four original timestamped RGB frames plus eight pinned raw Full/Heavy diagnostic panels were inspected, including missing poses and foreground occlusion. The raw 128 source/reference caches remain unchanged and are hash-bound.

## Next hypothesis, requiring a separate freeze

Requiring every ready pose to fit an acceptable phase-conditioned companion band can suppress valid cross-person preparatory movement. Do not repeatedly tighten that same scalar gate or discard the known-correct losses. A narrower future hypothesis is a causal guard for **persistent clear** start discrepancies using the existing reject bound and 160 ms confirmation, while retaining the current treatment of grey-zone/transient evidence and all active-attempt safeguards. That would be an additional, separately frozen experiment, not a threshold change or a promotion of this failed acceptable-band candidate. Test both transient and persistent faults, recovery, known-correct retention and independent subject generalization before any app change.

# Frozen model pixels under active CameraX

29 October 2026 local date. Production remains `872c9f7`, compiler9, readiness50/100. Previous actual-camera ABBA testing found only a partial preview contention effect; source pixels also varied. This separately frozen experiment holds model input pixels, generated VIDEO timestamps, model/thresholds and owner priority fixed while changing concurrent camera work. It is static-input capacity research, never camera-input pose accuracy, capture latency or sustained throughput qualification.

Use two existing pinned inputs: the original A1 virtual-room PNG from the preview ablation, and the Apache-2.0 upstream positive pose fixture. Decode/prepare each once with the existing640-edge policy. For each input run quiet, active-camera, active-camera, quiet in fixed order. Use one dedicated owner executor at priority−2, matching the prior actual analyzer observation, and a fresh reference-selected Full estimator per block. Every block uses8 warmup+24 measured calls and generated model timestamps `index*67ms`. Neither input nor expected timings can select a backend or threshold. Require identical prepared ARGB pixel hashes across all four conditions of each input and no mutation of borrowed pixels.

Quiet blocks call the adapter directly while no camera activity is open. Active blocks launch the unchanged camera activity and require three initial real results, retain its existing Preview+Analysis bindings, then replace only its analyzer callback for research. Clear the old analyzer and close its now-unused native estimator on its original executor; only the separate probe graph performs subsequent inference. The research callback converts/rotates actual CameraX frames using the original helper, records that cost, but deliberately feeds the pinned static bitmap into the probe. Record the captured frame's timestamp/rotation separately from the generated model time. Never attach the static prediction to the actual camera image or pretend its capture latency is measurable.

Preserve all32 rows per block, native and whole-estimator wall durations, owner/process CPU deltas, thread priority/ID, reset/recreation counters, raw prediction status and original camera startup observations. Owner CPU excludes native worker threads; process CPU includes other threads in this application and is not isolated native-inference CPU. At index8 save the exact model input and complete raw MP33 prediction; in active blocks also save the distinct actual camera input. Inspect both sources without combining their provenance. All exports occur outside timed estimator calls, but no delivered-FPS claim is made from this paced workload.

Eight blocks provide256 timing rows and192 measured calls. Unsupported CPU data stays unavailable. Preserve errors and partial results on failure; do not change sample counts after inspecting timings. A controlled timing effect may motivate a later optimization hypothesis; it cannot identify a universal root cause, change production, earn readiness points or establish human-rep precision. No validation/final skeletal trajectories, human annotation, learned weights or temporal acceptance rules are involved.

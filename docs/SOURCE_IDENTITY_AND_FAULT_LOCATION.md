# Source identity admission and mirrored fault location

On 25 October, two live comparator defects were reproduced and fixed without changing reference targets or motion thresholds.

An empty or whitespace-only tracker subject ID previously passed the live admission check. Confident angular observations could therefore arm and count a complete cycle without an identified tracked subject, although reference compilation already rejects the same missing provenance. Live admission now uses the same null-or-blank requirement. Losing identity interrupts the current attempt once, withholds continuation through its middle, and requires a fresh observed cycle after recovery. A tracker ID is provenance within a tracking session; it does not establish biometric identity.

An early-reversal fault previously named the reference driver feature even when source matching was explicitly mirrored. For example, a shallow movement measured at the right knee could produce a fault naming the left knee. Early-reversal events and finalized fault records now use the observed source feature, consistent with the existing clear-form-deviation mapping. Reversal confirmation, the fault timestamp, disqualification, range and count behavior are otherwise unchanged.

Three JVM regression methods fail with the preceding engine and pass with the fix. They cover 24 unidentified-stream combinations, four interrupted/recovered streams and 96 asymmetric shallow-movement combinations across all six policies, both configured sides, both mirror modes and 10/15/30/60 FPS. In the asymmetric controls only the measured limb is shallow; the opposite limb completes the full range. These are constructed controls, not measurements of human accuracy. Two Android instrumentation methods additionally execute unidentified-source admission and direct/mirrored early-reversal checks in the packaged engine.

The fixed-input comparison retains every field in all eight camera replay summaries. All 192 replayed source traces also match after omitting the preceding checkpoint's passive `evidence` field. Reference-only backend choices, original timestamps, counts, verdicts, faults and reference keys are unchanged. These recordings have valid tracker IDs and use direct matching, so they do not measure the prevalence of either fixed defect. Complete reference coverage remains 12/32 and capped coverage 10/32. The new comparison registry is `provenance-fault-summary`; earlier registries and raw MP33 are preserved. `scripts/audit_source_identity_fault.py` reproduces the strict summary/trace/development comparison after the replays and scoped JVM suite, and refuses to overwrite its resulting report.

The development skeletal replay remains exactly equal to `mirror-calibration-development-replay.json`: 31 correct-labelled and 27 incorrect-labelled repetitions counted. No validation or final-test trajectories are replayed for this change. The failed quality head, side-binding experiment and plane guard remain excluded from production. The uploaded reference remains the movement target; no threshold is widened and no new manual labels are introduced.

Verification comprises 268 scoped JVM tests (core 220, adapter 14, app 34), 64 Python tests, the frozen 2,688 mechanism controls, 124 controlled corruptions and 27 native functional tests (adapter 12, app 15) on the available API 36 emulator. All pass without failures or skips. Native results and immutable APK/test receipts are recorded in `models/source-identity-fault.provenance.json`. No new camera extraction or video alteration is introduced, and no exercising-person or ten-minute performance improvement is claimed. Original frame QA and the earlier failed soak remain in their prior immutable checkpoint.

The debug APK in the accompanying delivery contains these fixes and passive diagnostic support; its manifest binds the tested source and bytes. It remains experimental. These changes improve evidence handling and fault localization, not measured good-rep recall. Readiness remains **42.5/100**; live human-rep precision is unknown, independent-label gates remain unmet and final subjects 08–10 remain sealed. Next tuning work must address reference extraction or representation with evidence for both retained good movements and rejected incorrect movements; another veto alone cannot repair the demonstrated low recall.
